LOCAL DOCUMENT SEARCH ENGINE
IMPORTANT PROFESSOR DEMONSTRATION TESTS
=======================================

Use these tests during the project demonstration.

These are selected to demonstrate the core algorithms,
data structures, correctness, and real-world usability.

============================================================
TEST 1 — EXACT KEYWORD SEARCH
=============================

MENU:

```
1 → Search keyword
```

INPUT:

```
algorithm
```

EXPECTED:

```
Found in 3 documents.

03_graph_theory.txt
05_dijkstra.txt
06_machine_learning.txt
```

SHOW THE PROFESSOR:

```
Keyword
    ↓
HashMap
    ↓
Inverted Index
    ↓
Posting List
    ↓
Document IDs + Frequency
```

KEY POINT:

```
HashMap provides O(1) average keyword lookup.

Returning k matching documents takes O(k).
```

============================================================
TEST 3 — NEGATIVE PHRASE TEST
=============================

MENU:

```
2 → Search exact phrase
```

INPUT:

```
machine algorithms learning
```

EXPECTED:

```
0 exact matches
```

WHY THIS TEST MATTERS:

The individual words may occur in the documents, but the
exact sequence does not.

Therefore the search engine must reject the result.

This demonstrates that the system performs TRUE exact
phrase matching rather than simply checking whether all
words exist.

SHOW:

```
Word presence ≠ exact phrase match.
```

TEST 4 — SUFFIX ARRAY + CACHING
===============================

MENU:

```
2 → Search exact phrase
```

```
machine learning
```

```
6 → Suffix Array Status
```

```

```

Search:

```

```

again.

Then:

```

```

EXPECTED:

```

```

SHOW THE PROFESSOR:

```
Frequently accessed document
        ↓
Build Suffix Array
        ↓
Cache in memory
        ↓

```

SEARCH COMPLEXITY:

```
O(M log N)
```

IMPORTANT:

The suffix array must actually be constructed and reused,
not merely displayed as "BUILT".

============================================================
WHAT YOU CAN SAY DURING THE DEMO
================================

KEYWORD SEARCH:

```
"Instead of scanning all documents for every query,
I use an inverted index where the keyword is the key
in a HashMap and the value is its posting list."
```

PHRASE SEARCH:

```
"I first intersect the posting lists to reduce the
candidate documents, then use KMP to verify the exact
phrase."
```

SUFFIX ARRAY:

```
"For frequently accessed documents, I lazily build and
cache a suffix array so subsequent exact substring
searches can use binary search."
```

GRAPH:

```
"Each document is represented as a node. Citations and
sufficiently similar documents create weighted edges."
```

DIJKSTRA:

```
"The edge weight represents conceptual distance, so
Dijkstra finds the minimum-distance path between two
documents and gives us a possible reading progression."
```

RELIABILITY:

```
"I also tested invalid queries, nonexistent terms,
repeated searches, and unreachable paths to ensure the
system doesn't simply work for the happy path."
```
